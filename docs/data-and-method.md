# 数据与实验方法（第一阶段小试）

本文件记录第一阶段"数据与实验可行性小试"的口径、结果与限制，作为后续需求文档与架构设计的依据。

## 1. 研究问题与范围

- 场景：单灾种（暴雨）、日尺度 24 小时累计降水预警。
- 目标：证明"多源数据融合"相对单模式基线有可量化提升，并能向教务处说明对比口径。
- 非目标：八类灾害全量实现与实时应急决策。多灾种范围收敛的完整口径见 `requirements-v1.md` 的"多灾种扩展设计"一节。

## 2. 数据来源与许可

| 用途 | 接口 | 说明 |
| --- | --- | --- |
| 预报（主） | `previous-runs-api.open-meteo.com` | `*_previous_day1` 表示"在有效时刻前 24 小时签发的预报"，可模拟预警时刻可见的信息 |
| 标签 | `archive-api.open-meteo.com`（ERA5） | 事后再分析，**仅作代理标签，不是站点实测** |

- 许可：非商业用途，CC-BY 4.0，需署名；限速约 10,000 次/日。数据获取已做本地缓存，复跑不重复请求。
- 未使用 `single-runs-api` 作为主数据源：其归档仅自 2026-04-02 起（ECMWF IFS HRES 回溯至 2024-03-14），窗口过短。

## 3. 数据规模与覆盖

- 研究期：2024-02-01 ~ 2026-09-30（UTC）。起点取 2 月是**刻意规避** 2024-01 的归档起始边界——该月预报覆盖仅 300/744 小时。
- 站点：扩展为 9 个城市：武汉、广州、香港、上海、杭州、长沙、南昌、南宁、郑州。各城市 2024-02 后对齐样本均为 23,472 小时，预报和 ERA5 标签缺测率均为 0.0%。
- 日尺度测试年 2026 每个城市 267 天，合并样本 n=2,403；10mm/24h 正类 406，25mm/24h 正类 124。
- 选择依据：覆盖质量、地理分散性与暴雨事件数量；不把某一个城市的偶然结果当作总体结论。
- 旧的三城结果仍保留在历史 JSON 中，但报告主表使用九城合并结果。


## 4. 标签定义与局限

- 标签：ERA5 该日 24 小时累计降水 ≥ 阈值。分级参考中国降水标准：≥10mm 中雨、≥25mm 大雨、≥50mm 暴雨。系统内据此显示**教学风险等级**，不代表官方预警信号。
- **重要局限**：ERA5 是 0.25° 网格再分析，会平滑短时极值。实测武汉 2024-02~2026-09 中小时降水 ≥20mm/h 仅 3 次，无法作为小时极值标签；而 24 小时累计与预报的相关性达 0.83，是该数据能支撑的尺度。**报告不得将 ERA5 称为站点实测。**

## 5. 实验协议（无未来信息泄漏）

- 决策时刻为 UTC 日 D，特征全部来自 `previous_day1`，即签发于 D 前 24 小时的预报，提前量恒为 24 小时。
- 按**自然年**切分：训练 2024、验证 2025、测试 2026。测试年只评估一次。
- 对比协议固定，避免选择偏差：
  - 基线：ECMWF IFS 单模式预报 24 小时累计取固定阈值；
  - 改进：ECMWF/GFS/ICON/GEM 四模式等权融合后取同一阈值。

## 6. 记录在案的负结果

这三项都是先做错、被数据推翻的结论，保留以免重犯：

1. **小时尺度标签不可用**：ERA5 平滑掉短时极值，≥20mm/h 事件仅 3 次，评估退化。
2. **按行序 60/20/20 切分有陷阱**：验证段落在 11 月—次年 2 月旱季（暴雨事件为 0），阈值校准退化为"全报正"（召回 1.0、误报率 1.0），F1 被刷成 0.0072 的假最优。**强季节性数据必须按年或按雨季切分。**
3. **单源叠加辅助变量无增益**：在单一预报源上加入湿度、CAPE、露点等（多变量逻辑回归），测试集 AUC 反降（0.9682 → 0.9556），三个阈值下 F1 均低于基线（−9.65 / −10.69 / −6.67 点）。**增量信息来自"多源"而非"多变量"。**

## 7. 主结果：九城多源融合（合并评估）

测试年 2026，九城合并，n=2,403。基线固定为 ECMWF IFS 单模式，改进固定为四模式（ECMWF/GFS/ICON/GEM）等权平均；不按城市挑选最优单模式。

| 阈值 | 正类 | 方案 | 精确率 | 召回率 | 误报率 | F1 | AUC |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 10mm/24h | 406 | 基线 ECMWF | 0.7105 | 0.7857 | 0.0651 | 0.7462 | 0.9586 |
| 10mm/24h | 406 | 四模式融合 | **0.7620** | **0.8202** | **0.0521** | **0.7900** | **0.9720** |
| 25mm/24h | 124 | 基线 ECMWF | 0.5385 | 0.6774 | 0.0316 | 0.6000 | 0.9682 |
| 25mm/24h | 124 | 四模式融合 | **0.6814** | 0.6210 | **0.0158** | **0.6498** | **0.9702** |

- 10mm：ΔF1 = **+4.38 点**，自举 95% 区间 **[+1.57, +7.29]**，P(提升) = **0.998**。这是当前最稳健、建议写入摘要的主结果；精确率、召回率和 AUC 同时提升，误报率下降。
- 25mm：ΔF1 = **+4.98 点**，95% 区间 [−2.21, +11.62]，P(提升) = 0.923。可作为探索性结果，不能表述为统计确定的提升。
- 25mm 的融合召回率低于基线（0.6774→0.6210），但精确率翻升、误报率减半；这属于预警系统中的“减少误报—牺牲部分召回”权衡，不能说成所有指标都提升。

**建议答辩表述**：在九城合并、固定 2026 测试年、固定 24 小时提前量和相同 10mm/24h 标签下，四模式等权融合使 F1 从 0.7462 提升到 0.7900（+4.38 个百分点），误报率由 6.51% 降至 5.21%；自举 95% 区间为 [+1.57, +7.29]。这是真实、可复现且不过度夸大的结论。

**必须同时说明的限制**：
- 10mm/24h 是中雨级别，不能直接称为“严重暴雨预测准确率”。25mm 结果是大雨级别，50mm 更接近暴雨但样本仍少。
- 25mm 的增益主要来自决策点精度，不代表所有等级均提升；多模式在某些城市/阈值会输给单模式。
- ERA5 是代理标签，真实观测验证仍需单独完成。

### 7.1 指标进入系统

答辩时不能只展示离线 JSON，必须让运行中的系统展示同一组冻结结果：

- 将 `data/results/pooled.json` 按固定版本导入或作为只读快照提供，记录数据版本、测试年份、样本量、阈值和标签来源。
- API 提供实验指标查询；前端“指标对比页”展示基线 ECMWF 与四模式融合的精确率、召回率、误报率、F1、AUC 和自举区间。
- 页面只读展示冻结结果，不在浏览器重算模型；回放页的单条融合结果与指标页的汇总结果应能追溯到同一算法版本。
- 演示时必须同时显示限制：ERA5 是代理标签、10mm 为教学阈值、25mm 结果不确定性较大。

## 8. 复现命令

在 Ubuntu VM 的项目根目录激活项目虚拟环境后运行；依赖安装需要 `python3-venv`。

```bash
# 覆盖与事件数（选站点用）
python3 backend/coverage_report.py --site 武汉:30.5928:114.3055 --start 2024-01-01 --end 2026-09-30 --months

# 技能探测（判断目标尺度与阈值）
python3 backend/skill_probe.py --lat 30.5928 --lon 114.3055 --start 2024-02-01 --end 2026-09-30

# 单源多变量对比（负结果，保留）
python3 backend/evaluate.py --site 武汉 --lat 30.5928 --lon 114.3055 --start 2024-02-01 --end 2026-09-30 --threshold 25

# 多源融合（主结果）
python3 backend/fusion.py --site 武汉 --lat 30.5928 --lon 114.3055 --start 2024-02-01 --end 2026-09-30 --threshold 25
python3 backend/pooled.py --out data/results/pooled.json

# 汇总
python3 backend/summarize.py
```

## 9. 真实观测 API review（第一轮）

### 已跑通：NOAA GHCN-Daily

- 端点：`https://www.ncei.noaa.gov/data/global-historical-climatology-network-daily/access/{station}.csv`
- 武汉站 `CHM00057494`（WUHAN, CH）：HTTP 200，返回 1951 年起的日记录；`PRCP` 单位为 0.1mm，需除以 10 转成 mm。
- 数据列包含 `STATION, DATE, LATITUDE, LONGITUDE, NAME, PRCP, PRCP_ATTRIBUTES`，可以按日期与 ERA5 日累计对齐。
- **更新滞后不一致**：武汉、南宁、南昌目前止于 2025-08-24；长沙 `CHM00057687` 已更新到 2026-10-09。不能假设所有站点都覆盖当前测试年，接入时必须读取最后日期并报告覆盖率。
- 适用方式：作为 ERA5 代理标签的**独立历史交叉验证**，先选数据更新到测试年的站点；不宜直接替换九城全量标签。

### 已跑通但不可用：IEM ASOS

- 端点可返回 HTTP 200 和 CSV，但中国站 `ZHHH`（武汉）、`ZGGG`（广州）、`VHHH`（香港）2025 全年 `p01i` 均为 0，说明站点未报送降水组；“接口成功”不等于“观测有效”。不纳入实验。

### 待查：香港天文台 API

- 初次请求返回 HTTP 200 但提示参数无效，需要按其官方文档核对 `dataType` 与格式；暂不作为依赖。

### GHCN 交叉验证实测结果（长沙）

脚本：`backend/observation_eval.py`，结果：`data/results/ghcn_changsha_eval.json`。

| 标签阈值 | 共同日 | 正类 | 基线 F1 | 融合 F1 | ΔF1 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 10mm/日 | 366 | 48 | 0.5321 | 0.5217 | −1.04 点 |
| 25mm/日 | 366 | 22 | 0.4151 | 0.4762 | **+6.11 点** |

- 长沙站 `CHM00057687` 的共同日期范围为 2024-02-04 至 2026-09-30，但有效记录分布为 2024 年 309 天、2026 年 57 天，**缺少 2025 年**，不能把它当作完整的跨年独立测试集。
- 25mm/日结果支持“融合在较高降雨阈值上可能减少误报”：精确率 0.3548→0.5000，误报率 0.0581→0.0291，但召回率 0.5000→0.4545，存在漏报—误报权衡。
- 10mm/日结果没有提升，不能声称融合在所有阈值都有效。
- GHCN `PRCP` 是站点日累计，而 Open-Meteo 预报和 ERA5 标签按 UTC 日聚合；站点观测日界线可能不同，因此这里只做方向性独立验证，不并入九城主结果。
