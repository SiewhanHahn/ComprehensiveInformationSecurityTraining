# C2 雪灾历史回放实施计划

> **For agentic workers:** 使用 `executing-plans` 和 `test-driven-development` 按项执行。

**目标**：用站点附近真实归档预报计算未来 24 h 强降雪教学风险，独立展示同站同窗口的事后天气编码。只有原业务归档在窗口前有证据且达到阈值的案例（新奥尔良 HRRR）可制单；济南对照不混作已证实原发的样本。

**架构**：FastAPI 回放预报与事后记录分开返回；结构化预报快照进既有 `0008`，复用 B 工作流。Vue 以 24 小时降雪条带区分风险和时段，预警详情重用预报卡但不显示事后记录。依据：[验收表](../../c-eight-hazard-acceptance.md)、[来源核对](../../c2-snow-source-preflight.md)。

**全局约束**：UTC、`(start, end]` 小时末标、24 个有效时次、`cm`/`°C`。累计 ≥10.00 cm 触发教学研判，不冒称预警标准或灾损。温度用于解释，不做第二次相态分类。缺测不报低风险；错误单位不换算或猜测。预报无观测回填。C1 和台风数据不动。

- [x] **规则**：先在 `tests/test_snow.py` 锁定 20.19/12.74/0.00 cm、24 h 框、12 小时保守时钟、等阈、重复时次、缺测和错误单位。新增 `assessment_schemas.py` 类型、`services/snow.py` 及两个来源分离的本地样本；重跑红绿测试。
- [x] **接口/流程**：在同一测试文件添加拒绝越权、CSRF、任意快照输入和未达标制单的集成测试；核对正式草稿、发布、通知、反馈和审计数据。实现 `GET /snow/cases`、`GET /snow/cases/{case_id}/assessment`、`POST /warnings/snow` 及 `WarningDetailOut.snow_assessment`。不增加迁移，不改暴雨融合。
- [x] **页面**：先测案例切换不会被旧请求覆盖，注册表标识正确，详情不渲染雨量融合。实现 `Snow.vue` 和 `SnowEvidence.vue`；条带支持逐时表格，来源和事后证据单列，教学字样一直可见。仅授权用户在达标受控案例看到制单入口。
- [x] **验收**：复查固定 SHA；新独立 Compose 项目/卷/QA 回环端口，从干净归档启用全量集成测试、前端回归与构建。写入前核对版本；实测雪灾正反例、草稿至撤回审计，再回归台风/C1/B。错误单位由契约测试演示；不添加不必要的外部输入端点。记录结果，再创建局部标签；不推送。
