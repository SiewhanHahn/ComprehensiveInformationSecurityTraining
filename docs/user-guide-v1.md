# 用户操作与答辩演示说明 V1

## 1. 状态

本文说明当前代码中的使用方式；部署、接口和浏览器流程是否运行验证，以 `docs/test-report-v1.md` 的后续证据为准，不在本文预先声称实测通过。

## 2. 启动与停止

前置条件：Ubuntu 26.04 VM 已安装 Docker CE 与 Compose 插件，项目目录为 `~/Projects/ComprehensiveInformationSecurityTraining`。

```bash
cd ~/Projects/ComprehensiveInformationSecurityTraining
cp .env.example .env
# 编辑 .env，设置本地随机密码和 APP_SECRET_KEY；不要把 .env 提交
docker compose up --build -d
docker compose ps
```

首次启动会依次执行 MySQL/Redis 健康检查、Alembic 迁移、seed（导入离线样本、创建演示账号）和 API 启动。

验证：

```bash
curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8080/health/db
curl http://127.0.0.1:8080/health/redis
```

访问 `http://127.0.0.1:8080`。若从宿主机访问 VM，使用 SSH 隧道：

```bash
ssh -L 18080:127.0.0.1:8080 shawn@192.168.100.128
# 浏览器打开 http://127.0.0.1:18080
```

停止：

```bash
docker compose down
```

不要使用 `docker compose down -v`，除非确认要删除 MySQL 数据卷。

## 4. 终期演示：先看年份，再看提升，最后换城市

**C1 现场演示专用**：用 `checkpoint/c1-rain` 的 Git 归档、单独的 Compose 项目与卷。普通历史 B 为 8080、历史暴雨实例为 18080、B 验收为 18181；不要占用或覆盖它们。C1 新建演示默认 **18280**，本次可丢弃 QA 使用 **18281**。B/C 若在同一主机名下，仅换端口不能隔离会话 Cookie；请使用不同浏览器配置文件（或相互独立的浏览器上下文）。

在有验收标签的 VM 仓库使用 Bash，事先准备私有配置（替换 `.env.example` 的所有占位符），设置 `C1_ENV_FILE` 为其绝对路径。第一次构建可能需要联网；演示前预热镜像并准备好样本。

```bash
set -euo pipefail
: "${C1_ENV_FILE:?请提供私有配置的绝对路径}"
rev=$(git rev-parse 'checkpoint/c1-rain^{commit}')
dir=$(mktemp -d "$HOME/rain-c1-demo-XXXXXX")
git archive "$rev" | tar -xf - -C "$dir"
install -m 600 "$C1_ENV_FILE" "$dir/.env"
cd "$dir"
export COMPOSE_PROJECT_NAME=rain-c1-demo COMPOSE_FILE=compose.yaml:compose.defense.yaml DEFENSE_PORT=18280
docker compose up --build -d
test "$(docker compose port frontend 80)" = '127.0.0.1:18280'
base=http://127.0.0.1:18280
test "$(curl -fsS --retry 5 --retry-all-errors "$base/build-revision.txt")" = "$rev"
curl -fsS "$base/health/db"; curl -fsS "$base/health/redis"
```

在 VM 浏览器打开 `http://127.0.0.1:18280`；宿主机可用 `ssh -N -L 19280:127.0.0.1:18280 shawn@<VM地址>` 再打开 `http://127.0.0.1:19280`。任一版本/端口检查失败则停止；不要把另一个实例的 200 响应当作成功。不要在演示环境跑全量写入测试或删除卷。

1. **年份与来源**：分析员登录「指标对比」。九城实验用归档预报，不是实时预测；研究期 2024-02-01 至 2026-09-30，2026 年测试，原始下载日期未记录。不能说“只有往年的”，也不能说“9 月底是平台最新日期”。
2. **一条样本**：「历史回放」默认长沙 2024-03-27，选 25 mm，点「回放」。ECMWF/GFS/ICON/GEM 的 `32.7 / 30.7 / 19.6 / 35.5` 平均为 **29.625 mm**，超过阈值。ERA5 的 **29.6 mm** 只作事后参考，两者不是同一个数。
3. **整体提升**：回到「指标对比」。10 mm 下同一批 2,403 个城市日，F1 `0.7462 → 0.7900`，误报 `130 → 104`，漏报 `87 → 73`。切到 25 mm：误报减少，但召回率下降。若追问个例，用内置回放对照：南宁 2024-03-09 融合消除一次误报（43 → 19.850，参考 13.6）；杭州 2024-03-27 融合反而漏报（30.9 → 23.250，参考 25.6）。个例用于解释，不替代九城统计。
4. **换南京文件**：「历史回放 → 外部城市降水试算」。下载南京样例并选择它，点「运行试算」，应出现 7 行。10 月 3 日四路为 `2.1 / 5.2 / 3.3 / 13.0`，融合 **5.9 mm**，ERA5 **5.4 mm**。选的是 10 月首个完整星期，不是挑选成功个例；这批不计算 F1，不改变九城结果。换「缺一列示例」应指出第 1 行缺 `gem_global`，且不留上一批结果。
5. **正式预警是另一条流程**：回到内置长沙回放，以分析员制单提交，换独立审核员批准发布，再展示通知、响应任务、反馈与管理员审计。外部试算没有发布入口；审计只记操作者、阈值、条数等元数据。不要用试算冒充正式预警。

文件为 UTF-8 JSON（1–200 行，最大 256 KiB），从页面下载模板；仅支持四路日累计降水（mm），不自动转换任意气象台表格。`reference_mm`、`reference_type` 成对可选；`STATION_OBS` 代表文件提供者声明的实测，系统不认证其来源。查看权限、字段和拒绝规则见[接口文档](interface-design-v1.md#trial)。

## 4.2 订阅与站内通知（B 档第一刀）

演示前先在「通知中心」用 `viewer_demo` 订阅「暴雨 / 全部城市」，再由审核员发布一条新预警：

1. 普通用户进入「通知中心」（顶栏铃铛或「预警 → 通知中心」），在订阅设置里选灾种与城市，点「添加订阅」。
2. 切换审核员发布该预警，普通用户的顶栏铃铛出现未读角标。
3. 回到通知中心，看到「预警发布」通知，点「标记已读」后角标归零；「查看预警」跳转详情。
4. 说明投递范围按「灾种 × 城市」匹配，通知只属于收件人本人；撤回同样会通知订阅者。
5. 说明「先发布、后订阅」由独立的 `scheduler` 服务定时补投，重复扫描不会产生重复通知（`notifications.dedupe_key` 唯一索引）。

## 4.3 响应任务与超时升级（B 档第二刀）

预警发布时会自动给创建者派一条处置任务，时限默认 24 小时。演示时**先把时限与扫描间隔调小**，
否则现场等不到超时：

```bash
# .env（演示用）
RESPONSE_TASK_DUE_MINUTES=2
NOTIFICATION_SCAN_INTERVAL_SECONDS=30
```

然后 `docker compose up -d api scheduler` 让新配置生效。演示流程：

1. 分析员登录，进入「预警 → 任务看板」，查看「待处置」页签。
2. 审核员发布一条预警，刷新任务看板，出现一条指派给该分析员的待处置任务，显示处置时限。
3. 分析员点「接单」，任务进入「处置中」；填写处置说明后点「完成」，任务进入「已完成」。
4. 再发布一条预警但**先不处理**，等 2 分钟（或等到扫描间隔过去）后刷新：任务被标记「已逾期」，
   通知中心出现「任务超时」与「超时升级」两条通知（后者发给管理员）。
5. 打开预警详情，「响应任务」卡显示负责人、时限与升级次数；闭环 Stepper 的「响应」阶段随任务完成变绿。
6. 说明超时不改变任务状态，只是被标记并升级一次；重复扫描不会重复升级，也不会重复通知。

## 4.1 管理员用户管理

管理员登录后访问前端 `/users`。页面提供账号创建、分页列表、角色编辑、启用/停用和密码重置；所有写操作由服务端 `ADMIN`/RBAC 和 CSRF 校验保护，前端隐藏按钮不替代服务端授权。

- 创建：用户名为 3–64 位 ASCII 字母、数字、`_`、`.`、`-`；显示名称去首尾空白后 1–100 字符；密码 8–128 字符且不能全为空白；至少选择一个角色。
- 角色：可选 `ADMIN`、`ANALYST`、`REVIEWER`、`VIEWER`，至少保留一个；不能移除当前登录账号的 `ADMIN`，也不能停用活动中的最后一个管理员。
- 停用：不能停用当前登录账号。停用不会删除已有 Session，但该账号下一次鉴权会被拒绝；重新启用后，尚未过期且 Redis 仍保留的 Session 可恢复使用。
- 重置密码：只提交新密码，不回显旧密码；不会注销已有 Session。Session TTL 到期仍需重新登录；API 重启不会主动删除 Redis 中尚未过期的 Session，能否恢复取决于 Redis 持久性和可用性。
- 操作会产生 `USER_CREATE`、`USER_STATUS_CHANGE`、`USER_ROLES_CHANGE` 或 `USER_PASSWORD_RESET` 审计记录；审计详情由管理员在审计页查看。

如果接口返回 `403`，先确认当前账号仍启用并具有 `ADMIN` 角色，同时发送登录后获得的 CSRF Token；`409` 通常表示用户名重复、最后管理员保护或自我保护规则。

<a id="typhoon"></a>

## 台风教学演练（C2 子项）

1. 用[C2 验收入口](c2-typhoon-handoff.md)确认归档提交和站点版本，登录后选择「数据 → 台风路径」。不要将 C1 站点用于台风验收。
2. 选择天鸽、广州，核对 **144.3 km**；换到上海为 **1351.3 km**，不能建立草稿。再切回广州。预测显示的是实际签发后 24 h 内的离散点，不代表风圈、风雨或灾损。「事后核对」同刻位置与预测相差 **10.3 km**，不影响判定。
3. 用分析员填写并保存教学演练草稿，检查详情的单位是 km（不是 mm），再提交审核。另一位审核员在详情看到公报和签发证据，核对后批准、发布；分析员接单、完成并反馈，管理员在审计页核对发布和撤回。
4. 演示时不加载外部网站；只有点击「出处」链接需要联网。不能把教学演练发布当成正式气象预警，其他灾种的验收不由此替代。

<a id="lightning"></a>
## 雷电历史演练（C2 子项）

1. 在对应源码的隔离实例登录，选择「数据 → 雷电回放」。先看 2025-03-15 `(00:00, 06:00] UTC`：六时次峰值 **0.09**，02:00、03:00、04:00 UTC 达 **0.05** 教学界线。
2. 展开「独立事后核验」可见 01:46 和 02:33 的雷暴及闪电备注。切到 `(06:00, 12:00] UTC`：六值 **0.00**；`TSE06` 是上一轮结束，不应讲成当时又发生一次。抽样不是整窗无雷证明。
3. 回到首窗创建草稿，交另一账号审核、发布，再响应与反馈。预警详情只显示预报快照，不含事后报告。缺一个有效值就显示无法判断；不要把 LTNG 当成概率或落点预报。

## 基础预测：干旱教学试算

登录后打开「数据 → 基础预测」，填地点、UTC 首日、签发前已有连续少雨日数和未来七天逐日降水。示例的已有 9 天加七天少雨得 **16 天**。把第 5 天改为 **1.00 mm**，当日清零，第七天末剩 **2 天**。清空一格再算应显示「无法判断」，0 则是明确的零降水。试算不会留存输入、创建草稿或发布，是少雨持续性的教学判断，不是农业干旱预警。

## 5. 常见故障

| 现象 | 检查 |
| --- | --- |
| `permission denied /var/run/docker.sock` | 确认 `shawn` 在 `docker` 组并重新登录 |
| 镜像拉取失败 | 检查 `daemon.json` 镜像加速器可用性；必要时换可信源并固定摘要 |
| MySQL 不健康 | `docker compose logs mysql`；检查 `.env` 密码和卷状态 |
| API 503 | 检查 `/health/db`、MySQL 网络和迁移日志 |
| 登录后立刻失效 | 检查 Redis 是否运行、Session 过期时间和 Cookie 配置 |
