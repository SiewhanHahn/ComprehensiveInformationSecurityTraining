# 气象灾害预测与预警系统
## 需求规格说明书 V1

> 文档状态：课程项目 MVP 基线
> 适用范围：信息安全综合实训，B/S 架构，教学演示与历史回放
> 当前结论：系统是教学模拟平台，不作为真实应急预警发布系统

## 1. 项目背景与目标

### 1.1 背景

项目面向“监测—预测—研判—预警—发布—响应—反馈”闭环，当前先收敛到一个可验证、可运行的主场景：基于多种数值天气预报模式，对城市 24 小时累计降水进行风险预警。

老师要求能够说明相较已有方法的量化提升。当前已完成的实验固定为：

- 九个城市：武汉、广州、香港、上海、杭州、长沙、南昌、南宁、郑州；
- 24 小时固定预报提前量；
- 基线：ECMWF IFS 单模式；
- 改进：ECMWF、GFS、ICON、GEM 四模式等权融合；
- 主指标：F1、精确率、召回率、误报率、AUC；
- 主结果：10mm/24h 标签下，九城合并测试集 F1 从 0.7462 提升至 0.7900，提升 4.38 个百分点。

### 1.2 建设目标

1. 提供可复现的多源气象数据导入和融合结果。
2. 提供历史数据回放，展示从预报输入到预警结果的完整过程。
3. 提供基线与融合方案的指标对比，支持答辩时解释改进效果。
4. 提供预警研判、审核、发布、撤回和反馈记录。
5. 落实登录、角色权限、审批控制和操作审计等信息安全要求。

### 1.3 非目标

以下内容不纳入 MVP 的必须交付范围：

- 七类非暴雨灾种的完整数据接入、独立建模和同等深度的量化验证（保留扩展框架设计）；
- 真实短信、邮件、政务平台或应急平台发布；
- 对真实人员或财产作出自动化决策；
- 面向生产环境的高可用、容灾、集群和实时流处理；
- 复杂模型训练平台和在线自动调参；
- 将 ERA5 再分析数据称为地面实测真值。

### 1.4 交付范围与多灾种扩展设计

选题原题列出八类灾害场景。最终交付采用**“1 类端到端 + 7 类扩展框架”**口径：

- **暴雨（强降水）**：完成“监测—预测—研判—预警—发布—响应—反馈”完整闭环、可运行页面和可复现的量化对比，作为 MVP 主场景。
- **其余七类**：复用同一套预警状态机、角色权限、审批发布和审计结构；用户、角色、预警、审计数据模型可复用，灾种专属指标字段通过迁移扩展。文档给出数据源与判定指标映射，不承诺与暴雨同等的实现深度和独立量化验证。

这不是“只规划暴雨”：系统框架面向八类灾种，暴雨的离线模型实验已完成；端到端业务系统尚待实现和验证。答辩时必须明确这一边界，不把扩展设计说成已完成验证。

| 灾种 | 扩展所需数据源 | 判定指标（示意） | 与现有框架的关系 | 交付状态 |
| --- | --- | --- | --- | --- |

| 台风 | 台风路径/风圈预报 | 路径、最大风速、影响范围 | 复用预警状态机与发布审批 | 扩展框架 |

## 2. 用户角色

| 角色 | 主要职责 | 权限边界 |
| --- | --- | --- |
| 系统管理员 | 用户、角色、数据源和系统配置管理 | 管理配置和账号，不默认拥有业务发布权 |
| 气象分析员 | 查看数据、运行融合、生成预警草稿、填写研判意见 | 可创建和修改本人未提交的草稿，不能直接发布 |
| 预警审核员 | 审核预警草稿、退回修改、批准并发布、撤回 | 可审批、发布、撤回，不得修改原始预报数据 |
| 普通查看用户 | 查看已发布预警、历史回放和公开指标 | 只读，不能创建、审核或发布 |

MVP 中一个账号可以被授予一个或多个角色，但接口必须按角色检查权限，而不能只依赖前端隐藏按钮。

## 3. 系统边界

### 3.1 系统内

- 历史预报数据缓存与导入；
- 四模式预报数据对齐、质量检查和等权融合；
- 24 小时累计降水风险计算；
- 历史回放和结果查询；
- 预警草稿、研判、审批、发布、撤回、反馈；
- 指标和实验结果展示；
- 用户、角色和审计日志。

### 3.2 系统外

- Open-Meteo 预报数据服务；
- ERA5 再分析标签服务；
- NOAA GHCN-Daily 真实观测服务，仅作独立验证；
- 学校教务或真实应急发布平台；
- 短信、邮件和第三方消息渠道。

外部数据服务不可用时，系统应使用已缓存数据，并显示数据来源、缓存时间和数据状态，不应伪造“实时正常”。

## 4. 核心业务流程

### 4.1 历史回放流程

```text
选择城市和日期
  → 读取缓存的四模式 24 小时预报
  → 检查数据完整性和模型版本
  → 计算等权融合累计降水
  → 按预警阈值生成风险等级
  → 展示单模式/融合结果和标签对照
  → 写入回放记录
```

### 4.2 预警发布流程

```text
分析员生成预警草稿
  → 填写研判依据和影响范围
  → 提交审核
  → 审核员批准 / 驳回并填写意见
  → 批准后发布 / 撤回
  → 普通用户查看已发布内容
  → 分析员或管理员记录响应与反馈
```

强制状态流转：

```text
DRAFT → PENDING_REVIEW → APPROVED → PUBLISHED → WITHDRAWN
                         ↘ REJECTED → DRAFT
```

未经 `APPROVED` 的预警不得进入 `PUBLISHED`。已发布预警不得被普通更新操作覆盖，只能通过撤回或新增修订记录改变状态。

## 5. 功能需求

### FR-01 用户登录与会话

- 用户使用账号和密码登录。
- 密码不得以明文存储；服务端保存带随机盐的强哈希摘要。
- 登录失败返回不泄露账号是否存在的通用提示。
- 登出后服务端会话或令牌失效。
- 受保护接口必须验证登录状态。

### FR-02 用户与角色管理

- 管理员可以创建、停用和重置用户账号。
- 管理员可以授予或撤销角色。
- 停用账号不能登录，已有会话在下一次鉴权时失效。
- 角色变更必须写入审计日志。

### FR-03 数据源与数据集

- 系统记录数据源名称、数据类型、接口、许可说明、版本或抓取时间。
- 导入数据前检查城市、时间、模式和数值字段。
- 记录缺测、重复、时间乱序和异常数值。
- 数据集应能标识“预报数据”“ERA5 代理标签”“GHCN 独立观测”。
- 不同标签来源不得在界面或报告中混称为同一种真值。

### FR-04 多模式融合

- 支持 ECMWF IFS、GFS、ICON、GEM 四个模式。
- 默认使用四模式等权平均。
- 保存参与融合的模式列表、权重、时间窗口和算法版本。
- 缺少任一必需模式时，默认不生成正式预警，只显示数据不完整状态；历史回放可明确标记后查看部分结果。
- 融合结果必须可追溯到各单模式输入。

### FR-05 预警计算

- 支持 10mm/24h、25mm/24h、50mm/24h 等阈值配置。
- MVP 默认以 10mm/24h 作为主演示阈值，25mm/24h 作为较高等级示例。
- 预警计算输出教学风险等级、累计值、阈值、数据时间、预报提前量和模型版本。
- 默认提供基线单模式与融合结果并列展示。
- 自动计算不等于自动发布，计算结果必须先进入草稿或研判状态。
- 风险等级是**教学演示分级**，用于界面可视化，不代表国家气象台官方预警信号发布标准。

### FR-06 历史回放

- 用户可按城市、日期和阈值查询历史样本。
- 展示四个单模式值、融合值、阈值判断和代理标签或观测标签。
- 展示数据完整性、来源和缓存时间。
- 支持从某个历史时刻重新执行同一计算流程，结果应保持一致。

### FR-07 预警研判

- 分析员可以从计算结果创建预警草稿。
- 草稿必须填写灾种、区域、等级、有效时间、影响说明和研判依据。
- 分析员可保存草稿、提交审核或撤销未提交草稿。
- 提交后不得由原分析员直接发布。

### FR-08 审核与发布

- 审核员可以查看输入数据、融合结果、分析员意见和历史版本。
- 审核员可以批准、驳回并填写意见。
- 批准（APPROVE）与发布（PUBLISH）是审核员的两个独立动作：只有批准状态可以发布；发布与撤回由审核员执行，普通用户只读。
- 发布、撤回和驳回均记录操作者、时间、原因和对象版本。
- MVP 的”发布”仅改变系统内状态并供普通用户查看，不调用外部通知渠道。

### FR-09 响应与反馈

- 对已发布预警记录响应情况、处置备注和反馈内容。
- 反馈记录关联预警版本和操作者。
- 反馈不得修改原始预报和已发布内容，只能追加记录。

### FR-10 指标与实验结果

- 展示固定实验版本的样本数、切分方式、阈值和指标。
- 展示基线与融合方法的混淆矩阵和差异。
- 展示限制说明：ERA5 是代理标签，GHCN 结果是独立附录，不能混合。
- 禁止用户通过普通页面修改已冻结的主实验结果。

### FR-11 审计日志

至少记录：登录成功/失败、登出、用户和角色变更、数据导入、融合运行、草稿创建/修改、提交审核、批准、驳回、发布、撤回、反馈添加和权限拒绝。

## 6. 安全需求

### SEC-01 认证

- 所有管理和业务写操作要求认证。
- 密码哈希采用成熟算法和随机盐，不自行设计加密算法。
- 登录失败应限速或临时锁定，避免无限尝试。

### SEC-02 授权

- 服务端执行 RBAC，前端按钮隐藏不能代替权限检查。
- 普通用户只能读取已发布数据。
- 分析员不能审批自己的预警；审核员不能修改原始数据。
- 管理员配置权限变更需要审计。

### SEC-03 数据完整性与可追溯

- 预报输入、融合配置、结果和预警版本均保存来源与时间。
- 已发布记录采用追加版本或状态变更，不直接覆盖。
- 审计日志只允许追加，普通业务接口不能删除。

### SEC-04 输入与接口安全

- 城市、日期、阈值、分页和状态参数服务端校验。
- 不能把用户输入拼接为 SQL 或命令执行内容。
- 外部接口超时、错误和非法响应必须记录为数据源异常。
- API 不返回密码哈希、外部密钥或内部异常堆栈。

### SEC-05 密钥与隐私

- 外部接口地址和密钥通过环境变量或配置注入，不写入提交文件。
- 日志不记录密码、令牌和完整敏感凭证。
- 教学演示只使用模拟账号或脱敏数据。

## 8. MVP 验收标准

### AT-01 数据与模型

- 可导入或读取至少一个城市、一个历史日期的四模式缓存数据。
- 页面能够展示四模式输入、融合结果和阈值判断。
- 缺少模式输入时能显示不完整状态，不能伪造完整融合结果。

### AT-02 对比实验

- 页面能展示固定版本的基线与融合指标。
- 展示主结果：10mm/24h 九城合并 F1 `0.7462 → 0.7900`，提升 `4.38` 个百分点。
- 能查看样本量、测试年份和标签来源。

### AT-03 业务闭环

- 分析员可以生成预警草稿并提交审核。
- 审核员可以批准或驳回。
- 未批准预警无法发布。
- 已发布预警可以被普通用户查询。
- 可记录撤回和反馈。

### AT-04 安全控制

- 未登录访问受保护接口失败。
- 普通用户调用创建、审批、发布接口失败。
- 分析员不能调用审批或发布接口。
- 审核员不能审批自己创建的预警。
- 关键操作在审计日志中可查询。

### AT-05 可复现与故障

- 断开外部数据源后，已缓存历史回放仍可运行。
- 外部数据源失败时页面显示失败状态和缓存时间。
- 相同输入重复回放得到一致结果。

### AT-06 交付证据

- 每个验收项保留可复核证据：命令、日志、页面截图或数据库查询结果。
- 证据统一记录到 `docs/test-report-v1.md`，并注明采集时间和对应版本。
- 压缩包包含源代码、文档、`.env.example`、README、数据库初始化/迁移说明和演示账号说明；用于离线答辩的最小数据快照经许可检查后单独纳入，不包含真实密码和本地缓存大文件。

## 9. 演示脚本

1. 使用分析员账号登录。
2. 选择武汉或长沙、一个历史日期和 10mm/24h 阈值。
3. 展示 ECMWF、GFS、ICON、GEM 输入，以及等权融合值。
4. 展示融合结果、风险等级、代理标签和数据来源。
5. 展示实验指标：F1 0.7462→0.7900，误报率 0.0651→0.0521。
6. 分析员生成预警草稿并提交审核。
7. 切换审核员账号，批准预警。
8. 发布预警，切换普通用户查看。
9. 尝试用普通用户发布或用分析员审批，展示权限拒绝。
10. 打开审计日志，展示登录、生成、提交、审批和发布记录。
11. 关闭外部接口或模拟数据源失败，展示缓存回放和故障状态。
