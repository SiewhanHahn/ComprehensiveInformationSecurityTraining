# B 修复基线收口清单

适用分支 `worktree-phase-b-important-fixes`；不移动 `v0.3.0-phase-b` (`7181b93`)，不包含 C 版试算或新灾种。五批修复基线为 `c8b4182`。下表是本轮处置及复验入口；**必须另有同一源码提交的实测记录，才算最终基线**。不得用其他版本的计数销项。

| Important | 处理及验收方法 |
|---|---|
| 01 协议日期 | 导入严格 YYYY-MM-DD，自 2024-02-01 至 2026-09-30（含边界）；验证闰日、越界、坏行、空批。限定的是九城冻结样本，不是未来外部试算。 |
| 02 seed 误报 | 区分导入、幂等、保留既有可用数据、失败等结果；由实际上存在的预报决定可用性。验证坏文件和重入。 |
| 03 转换审计 | 发布、撤回支持可选原因；未给原因显式记“未提供原因”。驳回、发布和撤回记录对象版本；实际改稿才增加版本。管理员可看原因和版本。 |
| 04 草稿取消 | 拥有编辑权限的创建者取消自己的 DRAFT/REJECTED；终态 CANCELLED，保留归属、时间与审计，不发送通知或派发任务。独立验证 `0007`。 |
| 05 事件循环 | CSRF 会话 Redis 读取与过期清理放在线程池；测试检验事件循环仍响应，明确区分 401 和 503。 |
| 06 跨标签身份 | 聚焦及导航时核对会话；未读角标按认证版本和请求序号更新；身份变化不自动重放旧写操作。用两个标签/不同会话的组件回归。 |
| 07 审核列表 | 审核/预警列表与指标详情忽略旧响应；审核请求在行锁内比较所见版本+轮次，不接受对旧轮次的决定，无内容变更的重提也需重新核对。 |
| 08 编辑及重提 | 创建者能看驳回原因，可编辑、保存、在相同 public_id 上重提；二次审核、发布后仍限制编辑。API 回归 + 三角色浏览器流程。 |
| 09 影响说明 | 创建时必须非空，PATCH 不能清空，可省略未修改字段；旧空值草稿仍可读取、取消或补全，不能直接提交审核。不篡改历史已发布记录。 |

| Minor | 处理及复验点 |
|---|---|
| 01、02 | 每个模式与代理标签独立去重，不挤掉另一路完整数据；缺标签产生 `MISSING_PROXY` 质量记录且不误标预报侧。 |
| 03、04 | 相同 PATCH 不改版本或写审计；需求和接口按实际 `REJECTED → PENDING_REVIEW` 对齐。 |
| 05 | 创建请求不能解析城市/活动阈值返回 422；正常参数但资料不完整仍是 409。 |
| 06、07 | 限速事件每工作进程每分钟最多一条汇总警告，无凭据或逐条 DB 写入；请求号由服务生成，不采信浏览器给的编号。 |
| 08、09 | 权限拒绝中文标签；鉴权初始化区分依赖错误与已登出，允许重试。 |
| 10、11 | 通知机器可读的日期明确 UTC；装饰骨架和读屏状态文本分开。 |
| 12、13 | 通知尾页收缩时重取最后有效页；预警创建须同时满足角色、回放完整、融合达阈值。 |

## 验收与回退

- 查出并恢复两条被粘入相邻函数的集成测试：`test_full_lifecycle_and_guards`、`test_unauthenticated_is_rejected`。先单独收集，再在 MySQL/Redis 上运行，不能以跳过计通过。
- 使用**单独的 Compose 项目、端口与数据卷**。从候选 `git archive` 构建，运行 `/app/tests` 全套（`RUN_INTEGRATION=1` 和四个 QA 账号），`node --test tests/test_frontend_review.mjs tests/test_session_refresh_frontend.mjs`，以及前端生产构建。
- MySQL 用专用空数据库 `bcheck_migration_<12位十六进制>` 执行 `tests/manual_b_migration.py`：验证旧行、列和外键的 `0006→0007→0006→0007`；已有取消/审计版本数据时，应在第一条 ALTER 之前拒绝回退。实际更新先停写并备份；绝不在历史 B/C 实例做回退演习。
- 可选安装 Playwright/Chromium 或指定 `CHROMIUM_PATH`。只对隔离 QA 实例注入其演示密码和 `BCHECK_ALLOW_WRITE=1`，执行 `python tests/browser_b_acceptance.py --qa-url http://127.0.0.1:<QA端口> --expect-revision <完整SHA> --qa-proof <隔离核对记录.json>`（见 [离线部署的 QA 前置检查](offline-delivery.md#qa-preflight)；固定 B 标签按当时的脚本使用）。真实页面走三个独立会话，完成驳回、修改重提、发布、响应、反馈、撤回和审计。
- 这些回归不是生产容量测试或安全认证。迁移只在隔离库演习；不承诺无备份的生产数据降级。开源许可证未选，不做最终 push。
